# delivery-fee-checker

เว็บแอปหน้าเดียว (single HTML file, ไม่มี build tool) ให้ลูกค้า YOMO ข้าวไข่ลูกเขย เช็คก่อนสั่งว่าที่อยู่ตัวเองต้องเสียค่าส่งไหม เท่าไหร่ (ไม่ต้องกรอกยอดสั่งซื้อ) เลือกทางเลือก (จัดส่ง/มารับเอง) แล้วกดส่งข้อมูลจัดส่งให้ร้านทาง LINE ก่อนไปสั่งเมนูจริงที่หน้า POS ต่อ

**ใช้งานจริงได้ที่**: https://loponyflow-design.github.io/yomo-delivery-fee-checker/
(hosted ฟรีบน GitHub Pages จาก repo https://github.com/loponyflow-design/yomo-delivery-fee-checker — repo เป็น public เพราะ GitHub Pages ฟรีต้องใช้ public repo แต่ไม่มีข้อมูลลับอะไรอยู่ในนั้น ดูหัวข้อ "ข้อมูลที่เปิดเผยต่อสาธารณะ" ด้านล่าง)

ไม่มี backend, ไม่มี build step, เปิดไฟล์ `index.html` ในเบราว์เซอร์ได้ตรงๆ — มี dependency ภายนอก 2 อย่างเท่านั้น (ดูรายละเอียดด้านล่าง): Google Fonts (ฟอนต์) และ BigDataCloud (เติมที่อยู่จาก GPS)

**หน้าตาการใช้งาน**: เปิดเว็บมาครั้งแรกเห็นแค่แถบสถานะร้าน + ช่องเลือกระยะทาง (ยังไม่โชว์ราคา/ขั้นตอนอื่นเลย กันสับสน) → ลูกค้าเลือกระยะทาง (dropdown หรือกดปุ่ม GPS) → ทุกอย่างที่เหลือค่อยโผล่มาทีเดียว: เห็นค่าส่ง/ยอดฟรีส่งของช่วงนั้นทันทีเป็นตัวเลขใหญ่ๆ ไม่ต้องกรอกยอดสั่งซื้อล่วงหน้า → เลือกจัดส่ง/มารับเอง → เลือกเซ็ทแนะนำ (หรือ "เลือกเมนูเอง") → กรอกชื่อ+เบอร์โทร (ที่อยู่ใส่หรือไม่ใส่ก็ได้) → ตรวจสอบรายละเอียดในกล่องสรุป แล้วกดส่งข้อมูลจัดส่งให้ร้านทาง LINE → กด "สั่งเลย" ไปหน้า POS สั่งเมนูจริงต่อได้เลย

## แก้ยอดขั้นต่ำ / ค่าส่งต่อช่วงระยะทาง

เปิด `index.html` หาตัวแปร `ZONES` ในแท็ก `<script>` (ประมาณกลางไฟล์):

```js
var ZONES = [
  { label: "0-1 กม. (ในหมู่บ้าน)", threshold: 140, fee: 38, minKm: 0, maxKm: 1 },
  { label: "1-3 กม.",              threshold: 190, fee: 50, minKm: 1, maxKm: 3 },
  { label: "3-5 กม.",              threshold: 250, fee: 65, minKm: 3, maxKm: 5 },
  { label: "5-10 กม.",             threshold: 340, fee: 90, estimate: true, minKm: 5, maxKm: 10,
    note: "ระยะค่อนข้างไกล ทักแชทร้านทาง LINE ยืนยันก่อนสั่งได้ถ้าไม่แน่ใจ" }
];
```

- `threshold` = ยอดขั้นต่ำที่ฟรีส่ง (บาท)
- `fee` = ค่าส่งถ้ายอดยังไม่ถึง `threshold` (บาท)
- `estimate: true` = ขึ้นคำว่า "(เริ่มต้น)" กำกับค่าส่ง เผื่อราคาไม่ตายตัว
- `note` = ข้อความเตือนเพิ่มเติมที่จะโชว์ทั้งในหน้าเว็บและในสรุปที่คัดลอก (ใส่หรือไม่ใส่ก็ได้)
- `minKm` / `maxKm` = ช่วงระยะทาง (กม.) ที่ใช้ตอนลูกค้ากดปุ่ม "ใช้ตำแหน่งปัจจุบัน" เพื่อเลือกช่วงที่ตรงกับระยะจริงให้อัตโนมัติ ต้องเรียงต่อกันไม่มีช่องว่าง (max ของช่วงก่อน = min ของช่วงถัดไป) — `maxKm` ของช่วงสุดท้ายควรเท่ากับ `MAX_DELIVERY_KM` ด้านล่าง (ดูหัวข้อถัดไป) ไม่ใช้ `Infinity` แล้ว เพราะตอนนี้ร้านมีระยะจัดส่งสูงสุดจริง

เพิ่ม/ลบ/แก้ช่วงระยะทางได้อิสระ แค่แก้ array นี้ ไม่ต้องแตะโค้ดส่วนอื่น (แต่ถ้าเพิ่ม/ลด "ระยะจัดส่งไกลสุด" ต้องแก้ `MAX_DELIVERY_KM` คู่กันด้วย)

## ปุ่ม "ใช้ตำแหน่งปัจจุบัน" (GPS)

ใช้ `navigator.geolocation` ของเบราว์เซอร์ล้วนๆ ฟรี ไม่ต้องมี API key ไม่มีค่าใช้จ่าย ขอพิกัดแบบ `enableHighAccuracy: true` (ให้มือถือใช้ชิป GPS จริงแทนการประมาณจาก wifi/cell ที่หยาบกว่า) พิกัดจะถูกคำนวณในเบราว์เซอร์ของลูกค้าเองทั้งหมด ไม่ส่งไปไหนอัตโนมัติ (ยกเว้นตอนเรียก reverse geocode ดูหัวข้อถัดไป) จนกว่าลูกค้าจะกดส่งข้อมูลให้ร้านเอง

หาตัวแปรเหล่านี้ในไฟล์เดียวกัน:

```js
var SHOP_LAT = 13.778685908650033;
var SHOP_LNG = 100.4892634246037;
var ROAD_FACTOR = 1.3;
var MAX_DELIVERY_KM = 10;
```

- `SHOP_LAT` / `SHOP_LNG` = พิกัดร้าน หาได้จาก Google Maps (กดค้างที่หมุดร้าน จะเห็นตัวเลขพิกัดขึ้นมา)
- `ROAD_FACTOR` = ตัวคูณประมาณระยะทางถนนจริงจากระยะเส้นตรง (นกบิน) เพราะ GPS วัดได้แค่เส้นตรง ถ้าระบบเลือกช่วงผิดบ่อย (เช่น บ้านอยู่ไกลจริงแต่ระบบขึ้นช่วงใกล้) ให้ลองปรับค่านี้ขึ้น
- `MAX_DELIVERY_KM` = ระยะทางไกลสุดที่ร้านจัดส่งจริง — ถ้ากด "ใช้ตำแหน่งปัจจุบัน" แล้วคำนวณได้ไกลเกินนี้ หน้าเว็บจะขึ้นข้อความสีแดง "พื้นที่นี้อยู่นอกระยะจัดส่งของร้าน" แทนการเลือกโซน/คำนวณค่าส่งให้ (ไม่ทำให้ลูกค้าเข้าใจผิดว่าส่งได้) ต้องแก้ `maxKm` ของ `ZONES` ช่วงสุดท้ายให้เท่ากับค่านี้ด้วยเสมอ

ถ้าลูกค้าไม่กดปุ่มนี้ หรือไม่อนุญาตสิทธิ์ตำแหน่ง ยังเลือกช่วงระยะทางเองจาก dropdown ได้ตามปกติ ไม่มีผลกับการใช้งาน — แต่การเช็คระยะไกลสุดข้างต้นทำได้เฉพาะตอนกดปุ่ม GPS เท่านั้น (เพราะเป็นจุดเดียวที่แอปรู้ระยะทางจริง) ถ้าลูกค้าเลือกโซนเองจาก dropdown ระบบจะเชื่อค่าที่เลือกไปเลย ไม่เช็คซ้ำ

### เติมที่อยู่คร่าวๆ ให้อัตโนมัติ (reverse geocode)

หลังกด "ใช้ตำแหน่งปัจจุบัน" สำเร็จ แอปจะเรียก [BigDataCloud reverse-geocode-client API](https://www.bigdatacloud.com/free-api/free-reverse-geocode-to-city-api) (ฟรี ไม่ต้องมี API key) เพื่อแปลงพิกัดเป็นชื่อตำบล/เขต/จังหวัด แล้วเติมลงช่อง "ที่อยู่" ให้อัตโนมัติ — **เติมได้แค่ระดับตำบล/เขต** ไม่รู้บ้านเลขที่/ซอย/จุดสังเกต ลูกค้าจึงอาจต้องเพิ่มรายละเอียดพวกนี้เองอีกนิดหน่อยให้ไรเดอร์หาเจอ

- ถ้าลูกค้าพิมพ์ที่อยู่เองไว้ก่อนแล้ว ระบบจะไม่เขียนทับ (เติมเฉพาะตอนช่องว่างอยู่)
- ถ้าเรียก API ไม่สำเร็จ (เน็ตหลุด/บริการล่ม) แอปจะข้ามส่วนนี้ไปเฉยๆ ไม่ขึ้น error กวนใจ ลูกค้ายังพิมพ์ที่อยู่เองได้ตามปกติ
- นี่คือ dependency ภายนอกอย่างเดียวที่ "เห็นพิกัดลูกค้า" (ส่งพิกัดไปให้ BigDataCloud เพื่อแปลงเป็นชื่อสถานที่) — ถ้าไม่สบายใจ ลบส่วนเรียก `reverseGeocode()` ออกจาก `index.html` ได้ ฟีเจอร์อื่นจะยังทำงานปกติ (ปุ่ม GPS จะยังคำนวณระยะทาง/เลือกช่วงให้อัตโนมัติ แค่ไม่เติมที่อยู่ให้)

### ลิงก์ปักหมุด Google Maps (แม่นกว่าที่อยู่เป็นตัวหนังสือ)

ที่อยู่จาก reverse geocode ด้านบนแม่นได้แค่ระดับตำบล/เขต ไม่รู้บ้านเลขที่ — เพื่อให้ไรเดอร์เจอจุดจริงได้แม่นกว่านั้นโดยไม่ต้องพึ่ง API ที่มีค่าใช้จ่าย (เช่น Google Geocoding) แอปจึงสร้างลิงก์ปักหมุด `https://www.google.com/maps?q=lat,lng` จากพิกัด GPS ตรงจุดที่ลูกค้ากดปุ่มแทน แนบไว้เป็นบรรทัด "พิกัดตำแหน่ง (GPS)" ในข้อความสรุปที่ส่งให้ร้าน (ทั้งฝั่งไลน์และกล่องตรวจสอบรายละเอียด) — กดแล้วเห็นหมุดตำแหน่งจริงบนแผนที่ แม่นกว่าเดาที่อยู่จากตัวหนังสือเสมอ ลิงก์นี้จะไม่ปรากฏถ้าลูกค้าไม่ได้กดปุ่ม GPS (เลือกระยะทางเองจาก dropdown)

## สถานะร้านเปิด/ปิด

แถบสีเขียว/แดงหัวเว็บ (ใต้ header) บอกว่าร้านเปิดอยู่ตอนนี้ไหม เทียบจากเวลา+วันที่ใน**เครื่องของลูกค้าเอง** (ไม่ได้เช็คกับเซิร์ฟเวอร์ไหน) เปิด `index.html` หาตัวแปรเหล่านี้ (อยู่ใกล้ `ROAD_FACTOR`):

```js
var SHOP_OPEN_TIME = "06:30";
var SHOP_CLOSE_TIME = "15:00";
var SHOP_CLOSED_DAYS = [0]; // ตรงกับ Date.getDay(): 0=อาทิตย์, 1=จันทร์ ... 6=เสาร์
```

- แก้เวลาเปิด/ปิดตรงๆ ได้เลย ต้องเป็นฟอร์แมต `"HH:MM"` (24 ชั่วโมง)
- `SHOP_CLOSED_DAYS` ใส่ได้หลายวัน เช่น `[0, 1]` = หยุดทั้งอาทิตย์และจันทร์ ใส่ `[]` ถ้าเปิดทุกวันไม่มีวันหยุด
- ข้อความ "หยุดทุกวัน..." ที่โชว์ในแถบจะอัปเดตตามอัตโนมัติเมื่อแก้ `SHOP_CLOSED_DAYS` ไม่ต้องไปแก้ข้อความเองที่ไหนอีก
- แถบนี้แจ้งสถานะเฉยๆ ไม่ได้ปิดกั้นการใช้งานส่วนอื่น ลูกค้ายังเช็คราคา/กดส่งข้อมูลได้ตามปกติแม้ร้านจะปิดอยู่

ถ้าร้านเปิดอยู่แต่ใกล้ถึงเวลาปิดแล้ว (ภายใน `CLOSING_SOON_MINUTES` นาทีก่อนปิด ค่าเริ่มต้น 30 นาที) แถบจะเปลี่ยนเป็นสีเหลือง ขึ้นข้อความ "ร้านใกล้ปิดแล้ว! เหลืออีก X นาที ... รีบสั่งด่วน" แทน เพื่อสร้างความเร่งด่วนให้ลูกค้าตัดสินใจไว — แก้ตัวเลขนาทีได้ที่ `CLOSING_SOON_MINUTES` (อยู่ติดกับ `SHOP_CLOSED_DAYS`)

## เพิ่มเป็นไอคอนหน้าจอโฮม

รองรับ "Add to Home Screen" ทั้ง Android (มี `manifest.json` ให้ Chrome เสนอ "ติดตั้งแอป" ได้) และ iOS (มี `apple-touch-icon` + meta tag ให้ Safari ใช้ตอนกด "เพิ่มไปยังหน้าจอโฮม" จากปุ่มแชร์) เปิดแล้วจะเหมือนแอปเต็มจอ ไม่มีแถบที่อยู่เบราว์เซอร์ ไอคอนที่ใช้ตอนนี้เป็นสี่เหลี่ยมมุมโค้งสีแดง (`#BF1E2E`) ตัวอักษร "Y" สร้างจาก SVG ฝังเป็น data URI ไว้ในไฟล์เลย (ไม่ต้องมีไฟล์รูปแยก)

- ไฟล์ `manifest.json` (อยู่โฟลเดอร์เดียวกับ `index.html`) กำหนดชื่อแอป/สีธีม/ไอคอน แก้ `name`, `short_name`, `theme_color`, `background_color` ได้อิสระ
- อยากเปลี่ยนไอคอนเป็นรูปจริง (โลโก้ร้าน) แทนตัวอักษร "Y": ใช้ไฟล์ PNG สี่เหลี่ยมจัตุรัส (แนะนำ 512x512) วางไว้ในโฟลเดอร์นี้ แล้วแก้ `icons` ใน `manifest.json` กับ `<link rel="apple-touch-icon">` ใน `index.html` ให้ชี้ไปที่ไฟล์นั้นแทน data URI เดิม — **iOS Safari รองรับเฉพาะไฟล์ PNG จริงสำหรับ apple-touch-icon เท่านั้น** (SVG ที่ใช้อยู่ตอนนี้ใช้ได้ปกติกับ Android/Chrome แต่บน iOS อาจไม่ขึ้นไอคอนที่ตั้งใจไว้ ถ้าอยากให้ขึ้นชัวร์ทั้งสองระบบต้องเปลี่ยนเป็น PNG)

## ข้อความสร้างความมั่นใจ (trust strip)

ก่อนปุ่ม "สั่งเลย" มีข้อความ 3 บรรทัดสั้นๆ ช่วยให้ลูกค้าตัดสินใจสั่งง่ายขึ้น (สั่งตรงไม่ผ่านคนกลาง, ค่าส่งโปร่งใส, ไม่ต้องโหลดแอปเพิ่ม) หาได้จาก `class="trust-strip"` ใน `index.html` แก้ข้อความได้อิสระ

## ตัวเลขเปรียบเทียบราคากับแอปส่งอาหาร ("ประหยัดกว่า X บาท")

การ์ดเซ็ทแนะนำ (และกล่อง "ประหยัดรวม") โชว์ส่วนต่างราคาจริงเทียบกับสั่งผ่านแอปส่งอาหาร (Grab/Lineman/Shopee) โดยอิงโซนที่ลูกค้าเลือกอยู่แล้ว ไม่ต้องกรอกซ้ำ

เปิด `index.html` หาตัวแปร `APP_PRICE_BY_ZONE` (อยู่ต่อจาก `SETS`):

```js
var APP_PRICE_BY_ZONE = [
  { "เซ็ท A": 226, "เซ็ท B": 250, "เซ็ท C": 315, "เซ็ท D": 445 }, // โซน 0-1 กม.
  { "เซ็ท A": 232, "เซ็ท B": 256, "เซ็ท C": 321, "เซ็ท D": 451 }, // โซน 1-3 กม.
  { "เซ็ท A": 241, "เซ็ท B": 265, "เซ็ท C": 330, "เซ็ท D": 460 }, // โซน 3-5 กม.
  { "เซ็ท A": 366, "เซ็ท B": 390, "เซ็ท C": 458, "เซ็ท D": 585 }  // โซนเกิน 5 กม.
];
```

แต่ละตัวเลขคือ **ราคารวมจริงที่ต้องจ่ายเมื่อสั่งผ่านแอปส่งอาหาร** (รวมค่าส่งของแอปในตัวเลขนี้แล้ว) ได้จากการทดสอบสั่งจริง 1 ครั้งต่อจุด ที่จุดอ้างอิงใกล้ศูนย์กลางแต่ละโซน

- **ลำดับแถวต้องตรงกับ `ZONES` ด้านบน** (แถวที่ 1 = โซน 1 เป็นต้นไป) ถ้าเพิ่ม/ลบ/สลับลำดับโซนใน `ZONES` ต้องแก้ตารางนี้ให้ตรงกันด้วย
- **คีย์ในแต่ละแถวต้องตรงกับ `SETS[].name`** เป๊ะๆ (เช่น "เซ็ท A") ถ้าเพิ่ม/ลบ/เปลี่ยนชื่อเซ็ทใน `SETS` ต้องแก้คีย์ตรงนี้ให้ตรงกันด้วย
- ราคาแอปเปลี่ยนได้เรื่อยๆ ตามโปรโมชัน — ทดสอบสั่งใหม่เป็นระยะแล้วแก้ตัวเลขตรงนี้
- ถ้าคู่โซน/เซ็ทไหนสั่งตรงแพงกว่าหรือเท่าราคาแอป (ส่วนต่าง ≤ 0) หรือยังไม่มีตัวเลขในตาราง ระบบจะไม่โชว์ "ประหยัดกว่า" ให้เซ็ทนั้นในโซนนั้นเลย (ไม่โชว์ตัวเลข 0 หรือติดลบ)

## จำชื่อ-เบอร์โทรลูกค้าไว้ (localStorage)

ลูกค้าที่กรอกชื่อ+เบอร์แล้วครั้งหนึ่ง เปิดเว็บมาครั้งถัดไป (เครื่อง/เบราว์เซอร์เดิม) จะเห็นช่องชื่อ+เบอร์เติมไว้ให้อัตโนมัติ ไม่ต้องพิมพ์ซ้ำ — เก็บด้วย `localStorage` ของเบราว์เซอร์ลูกค้าเอง (คีย์ `yomo_dfc_contact`) **ไม่ได้จำที่อยู่ด้วย** เพราะที่อยู่จัดส่งอาจเปลี่ยนไปคนละที่ในแต่ละครั้ง ถ้าเบราว์เซอร์ปิดการใช้ localStorage (เช่น private mode บางตัว) ระบบจะข้ามไปเฉยๆ ลูกค้ายังกรอกเองได้ตามปกติ

## ปุ่มแชร์

ปุ่ม "แชร์เว็บนี้ให้เพื่อน" ท้ายหน้า ใช้ [Web Share API](https://developer.mozilla.org/en-US/docs/Web/API/Navigator/share) ของเบราว์เซอร์ (เปิด share sheet ของเครื่อง เลือกส่งทาง LINE/FB/อื่นๆ ได้เลย) ถ้าเบราว์เซอร์ไม่รองรับ (ส่วนใหญ่คือเดสก์ท็อป) จะคัดลอกลิงก์หน้านี้ใส่คลิปบอร์ดแทน หรือถ้าคัดลอกไม่ได้อีก จะโชว์ลิงก์ให้กดคัดลอกเอง ไม่มี dependency ภายนอกเพิ่ม

## แก้ลิงก์ POS

หาตัวแปร `POS_URL` ในไฟล์เดียวกัน แก้เป็นลิงก์สั่งเมนูจริงที่ต้องการ:

```js
var POS_URL = "https://mobile-order.wongnai.com/r/5889c073-df92-4506-aa40-dd52122ebb95";
```

## แก้ชื่อร้าน

หาตัวแปร `SHOP_NAME` แก้ชื่อที่จะแสดงบนหน้าเว็บและในข้อความสรุปที่ส่งให้ร้าน:

```js
var SHOP_NAME = "YOMO ข้าวไข่ลูกเขย";
```

## Deploy

Deploy ไว้แล้วที่ GitHub Pages (ดูลิงก์ด้านบนสุด) — ถ้าจะแก้ไขไฟล์แล้วให้เว็บอัปเดตตาม ให้ `git add`, `git commit`, `git push` จากโฟลเดอร์นี้ (repo: `loponyflow-design/yomo-delivery-fee-checker`) รอประมาณ 1 นาทีเว็บจะอัปเดตตาม

ไม่มี build step ทั่วไปก็เอาไฟล์ `index.html` ไปวางบนโฮสต์ static ที่ไหนก็ได้เช่นกัน เช่น Netlify (ลากไฟล์วาง) หรือแชร์ผ่านลิงก์ที่ให้เปิดไฟล์ตรงๆ

## ข้อมูลที่เปิดเผยต่อสาธารณะ

repo นี้เป็น public (ข้อจำกัดของ GitHub Pages แบบฟรี) เนื้อหาในไฟล์ที่ใครก็เห็นได้:

- ชื่อร้าน, พิกัดร้าน (lat/lng), ตารางยอดขั้นต่ำฟรีส่ง/ค่าส่งแต่ละโซน, ลิงก์ POS — ทั้งหมดนี้ตั้งใจให้ลูกค้าเห็นอยู่แล้วผ่านหน้าเว็บ ไม่ใช่ข้อมูลลับ

**ไม่มี** API key / credentials / secrets ใดๆ ในไฟล์นี้ (เป็น static app ล้วนๆ ไม่มี backend) และไม่มีเซิร์ฟเวอร์ไหนเก็บข้อมูลลูกค้าไว้เลย — ชื่อ/เบอร์/ที่อยู่ที่ลูกค้ากรอกอยู่ในเบราว์เซอร์ของลูกค้าเองเท่านั้น จนกว่าลูกค้าจะกดส่งข้อมูลทาง LINE เอง (ชื่อ+เบอร์ถูกจำไว้ใน `localStorage` ของเบราว์เซอร์ลูกค้าเองด้วยเพื่อความสะดวกครั้งถัดไป ดูหัวข้อ "จำชื่อ-เบอร์โทรลูกค้าไว้" — ยังอยู่ในเครื่องลูกค้าเท่านั้น ไม่ส่งไปที่ไหน)

ข้อยกเว้นเดียว: ตอนกดปุ่ม "ใช้ตำแหน่งปัจจุบัน" พิกัด GPS ของลูกค้าจะถูกส่งไปให้ BigDataCloud (บริการ reverse-geocode ภายนอก ดูหัวข้อด้านบน) เพื่อแปลงเป็นชื่อที่อยู่ — เป็นเพียงจุดเดียวที่มีการส่งข้อมูลตำแหน่งลูกค้าออกจากเบราว์เซอร์
