# delivery-fee-checker

เว็บแอปหน้าเดียว (single HTML file, ไม่มี build tool) ให้ลูกค้า YOMO ข้าวไข่ลูกเขย เช็คก่อนสั่งว่าที่อยู่ตัวเองต้องเสียค่าส่งไหม เท่าไหร่ (ไม่ต้องกรอกยอดสั่งซื้อ) เลือกทางเลือก (จัดส่ง/มารับเอง) แล้วคัดลอกสรุปไปวางในช่อง Note ของระบบ POS ตอนสั่งเมนูจริง หรือกดปุ่ม "สั่งเลย" ไปหน้าสั่งเมนูได้ทันที

**ใช้งานจริงได้ที่**: https://loponyflow-design.github.io/yomo-delivery-fee-checker/
(hosted ฟรีบน GitHub Pages จาก repo https://github.com/loponyflow-design/yomo-delivery-fee-checker — repo เป็น public เพราะ GitHub Pages ฟรีต้องใช้ public repo แต่ไม่มีข้อมูลลับอะไรอยู่ในนั้น ดูหัวข้อ "ข้อมูลที่เปิดเผยต่อสาธารณะ" ด้านล่าง)

ไม่มี backend, ไม่มี build step, เปิดไฟล์ `index.html` ในเบราว์เซอร์ได้ตรงๆ — มี dependency ภายนอก 2 อย่างเท่านั้น (ดูรายละเอียดด้านล่าง): Google Fonts (ฟอนต์) และ BigDataCloud (เติมที่อยู่จาก GPS)

**หน้าตาการใช้งาน**: ลูกค้าเลือกระยะทาง (dropdown หรือกดปุ่ม GPS) → เห็นค่าส่ง/ยอดฟรีส่งของช่วงนั้นทันทีเป็นตัวเลขใหญ่ๆ ไม่ต้องกรอกยอดสั่งซื้อล่วงหน้า → เลือกจัดส่ง/มารับเอง → กด "สั่งเลย" ไปหน้า POS ได้เลย หรือกรอกชื่อ+เบอร์โทร (ที่อยู่ใส่หรือไม่ใส่ก็ได้) แล้วคัดลอกสรุปไปวางใน Note ก่อนก็ได้

## แก้ยอดขั้นต่ำ / ค่าส่งต่อช่วงระยะทาง

เปิด `index.html` หาตัวแปร `ZONES` ในแท็ก `<script>` (ประมาณกลางไฟล์):

```js
var ZONES = [
  { label: "0-1 กม. (ในหมู่บ้าน)", threshold: 115, fee: 38, minKm: 0, maxKm: 1 },
  { label: "1-3 กม.",              threshold: 135, fee: 46, minKm: 1, maxKm: 3 },
  { label: "3-5 กม.",              threshold: 180, fee: 61, minKm: 3, maxKm: 5 },
  { label: "เกิน 5 กม.",           threshold: 205, fee: 70, estimate: true, minKm: 5, maxKm: Infinity,
    note: "ระยะไกล ทักแชทร้านเพื่อยืนยันค่าส่งอีกครั้ง" }
];
```

- `threshold` = ยอดขั้นต่ำที่ฟรีส่ง (บาท)
- `fee` = ค่าส่งถ้ายอดยังไม่ถึง `threshold` (บาท)
- `estimate: true` = ขึ้นคำว่า "(เริ่มต้น)" กำกับค่าส่ง เผื่อราคาไม่ตายตัว
- `note` = ข้อความเตือนเพิ่มเติมที่จะโชว์ทั้งในหน้าเว็บและในสรุปที่คัดลอก (ใส่หรือไม่ใส่ก็ได้)
- `minKm` / `maxKm` = ช่วงระยะทาง (กม.) ที่ใช้ตอนลูกค้ากดปุ่ม "ใช้ตำแหน่งปัจจุบัน" เพื่อเลือกช่วงที่ตรงกับระยะจริงให้อัตโนมัติ ต้องเรียงต่อกันไม่มีช่องว่าง (max ของช่วงก่อน = min ของช่วงถัดไป)

เพิ่ม/ลบ/แก้ช่วงระยะทางได้อิสระ แค่แก้ array นี้ ไม่ต้องแตะโค้ดส่วนอื่น

## ปุ่ม "ใช้ตำแหน่งปัจจุบัน" (GPS)

ใช้ `navigator.geolocation` ของเบราว์เซอร์ล้วนๆ ฟรี ไม่ต้องมี API key ไม่มีค่าใช้จ่าย และพิกัดของลูกค้าไม่ถูกส่งไปที่ไหนเลย (คำนวณในเบราว์เซอร์ของลูกค้าเองทั้งหมด)

หาตัวแปรเหล่านี้ในไฟล์เดียวกัน:

```js
var SHOP_LAT = 13.778685908650033;
var SHOP_LNG = 100.4892634246037;
var ROAD_FACTOR = 1.3;
```

- `SHOP_LAT` / `SHOP_LNG` = พิกัดร้าน หาได้จาก Google Maps (กดค้างที่หมุดร้าน จะเห็นตัวเลขพิกัดขึ้นมา)
- `ROAD_FACTOR` = ตัวคูณประมาณระยะทางถนนจริงจากระยะเส้นตรง (นกบิน) เพราะ GPS วัดได้แค่เส้นตรง ถ้าระบบเลือกช่วงผิดบ่อย (เช่น บ้านอยู่ไกลจริงแต่ระบบขึ้นช่วงใกล้) ให้ลองปรับค่านี้ขึ้น

ถ้าลูกค้าไม่กดปุ่มนี้ หรือไม่อนุญาตสิทธิ์ตำแหน่ง ยังเลือกช่วงระยะทางเองจาก dropdown ได้ตามปกติ ไม่มีผลกับการใช้งาน

### เติมที่อยู่คร่าวๆ ให้อัตโนมัติ (reverse geocode)

หลังกด "ใช้ตำแหน่งปัจจุบัน" สำเร็จ แอปจะเรียก [BigDataCloud reverse-geocode-client API](https://www.bigdatacloud.com/free-api/free-reverse-geocode-to-city-api) (ฟรี ไม่ต้องมี API key) เพื่อแปลงพิกัดเป็นชื่อตำบล/เขต/จังหวัด แล้วเติมลงช่อง "ที่อยู่" ให้อัตโนมัติ — **เติมได้แค่ระดับตำบล/เขต** ไม่รู้บ้านเลขที่/ซอย/จุดสังเกต ลูกค้าจึงอาจต้องเพิ่มรายละเอียดพวกนี้เองอีกนิดหน่อยให้ไรเดอร์หาเจอ

- ถ้าลูกค้าพิมพ์ที่อยู่เองไว้ก่อนแล้ว ระบบจะไม่เขียนทับ (เติมเฉพาะตอนช่องว่างอยู่)
- ถ้าเรียก API ไม่สำเร็จ (เน็ตหลุด/บริการล่ม) แอปจะข้ามส่วนนี้ไปเฉยๆ ไม่ขึ้น error กวนใจ ลูกค้ายังพิมพ์ที่อยู่เองได้ตามปกติ
- นี่คือ dependency ภายนอกอย่างเดียวที่ "เห็นพิกัดลูกค้า" (ส่งพิกัดไปให้ BigDataCloud เพื่อแปลงเป็นชื่อสถานที่) — ถ้าไม่สบายใจ ลบส่วนเรียก `reverseGeocode()` ออกจาก `index.html` ได้ ฟีเจอร์อื่นจะยังทำงานปกติ (ปุ่ม GPS จะยังคำนวณระยะทาง/เลือกช่วงให้อัตโนมัติ แค่ไม่เติมที่อยู่ให้)

## ข้อความสร้างความมั่นใจ (trust strip)

ก่อนปุ่ม "สั่งเลย" มีข้อความ 3 บรรทัดสั้นๆ ช่วยให้ลูกค้าตัดสินใจสั่งง่ายขึ้น (สั่งตรงไม่ผ่านคนกลาง, ค่าส่งโปร่งใส, ไม่ต้องโหลดแอปเพิ่ม) หาได้จาก `class="trust-strip"` ใน `index.html` แก้ข้อความได้อิสระ

**ยังไม่มี**: ตัวเลขเปรียบเทียบราคา/ค่าส่งกับ Grab, Lineman, Shopee (เช่น "ประหยัดกว่า X บาท") — รอตัวเลขจริงจากร้าน (ส่วนต่างราคาเมนูบนแอป หรือค่าส่งเฉลี่ยบนแอปพวกนี้) ก่อนถึงจะเพิ่มบรรทัดเปรียบเทียบแบบมีตัวเลขได้ ไม่อยากเดาราคาคู่แข่งเอง

## แก้ลิงก์ POS

หาตัวแปร `POS_URL` ในไฟล์เดียวกัน แก้เป็นลิงก์สั่งเมนูจริงที่ต้องการ:

```js
var POS_URL = "https://mobile-order.wongnai.com/r/5889c073-df92-4506-aa40-dd52122ebb95";
```

## แก้ชื่อร้าน

หาตัวแปร `SHOP_NAME` แก้ชื่อที่จะแสดงบนหน้าเว็บและในสรุปที่คัดลอก:

```js
var SHOP_NAME = "YOMO ข้าวไข่ลูกเขย";
```

## Deploy

Deploy ไว้แล้วที่ GitHub Pages (ดูลิงก์ด้านบนสุด) — ถ้าจะแก้ไขไฟล์แล้วให้เว็บอัปเดตตาม ให้ `git add`, `git commit`, `git push` จากโฟลเดอร์นี้ (repo: `loponyflow-design/yomo-delivery-fee-checker`) รอประมาณ 1 นาทีเว็บจะอัปเดตตาม

ไม่มี build step ทั่วไปก็เอาไฟล์ `index.html` ไปวางบนโฮสต์ static ที่ไหนก็ได้เช่นกัน เช่น Netlify (ลากไฟล์วาง) หรือแชร์ผ่านลิงก์ที่ให้เปิดไฟล์ตรงๆ

## ข้อมูลที่เปิดเผยต่อสาธารณะ

repo นี้เป็น public (ข้อจำกัดของ GitHub Pages แบบฟรี) เนื้อหาในไฟล์ที่ใครก็เห็นได้:

- ชื่อร้าน, พิกัดร้าน (lat/lng), ตารางยอดขั้นต่ำฟรีส่ง/ค่าส่งแต่ละโซน, ลิงก์ POS — ทั้งหมดนี้ตั้งใจให้ลูกค้าเห็นอยู่แล้วผ่านหน้าเว็บ ไม่ใช่ข้อมูลลับ

**ไม่มี** API key / credentials / secrets ใดๆ ในไฟล์นี้ (เป็น static app ล้วนๆ ไม่มี backend) และไม่เก็บข้อมูลลูกค้าไว้ที่ไหน — ชื่อ/เบอร์/ที่อยู่ที่ลูกค้ากรอกอยู่ในเบราว์เซอร์ของลูกค้าเองเท่านั้น จนกว่าลูกค้าจะกดคัดลอกไปวางเอง

ข้อยกเว้นเดียว: ตอนกดปุ่ม "ใช้ตำแหน่งปัจจุบัน" พิกัด GPS ของลูกค้าจะถูกส่งไปให้ BigDataCloud (บริการ reverse-geocode ภายนอก ดูหัวข้อด้านบน) เพื่อแปลงเป็นชื่อที่อยู่ — เป็นเพียงจุดเดียวที่มีการส่งข้อมูลตำแหน่งลูกค้าออกจากเบราว์เซอร์
